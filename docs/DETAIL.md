# 插件版本体检

每天自动核对一次当前配置里装的插件，看有没有新版本，结果在 **设置 → 插件 → 版本** 里看。

## 它做什么

- 每次体检都重新读各配置的 `package.json`，所以**新装的插件下一次体检就会自动出现**，不需要改代码。
- 依赖来自 npm 的，比 registry 上的 `latest`；来自 GitHub 的（`github:` / `git+https://…`），比仓库 `main`（或 `master`）分支 `package.json` 里的版本。
- 结果存一份到 `~/.dsh/plugin-watch/report.json`，重启后先读这份，超过 22 小时才重新体检。
- 设置页里有「重新检查」按钮，随时手动跑一次。

## 它不做什么

- **不会自动重启客户端**：自动装好的版本要等下次开客户端才生效。
- 只自动装「补丁号」变化的（比如 1.5.6 → 1.5.7），主次版本变了（1.5.6 → 1.6.0）只提醒；来自 GitHub 的也不自动装。
- 自动安装只在凌晨 4–6 点之间跑，一天最多一次，装之前先把 `package.json` / lockfile / workspace 配置备份到 `~/.dsh/plugin-watch/backup/`。
- 不判断版本兼容性，也不看 changelog；只知道「有没有更新的版本」。
- 网络查不到时那一行标「查询失败」，不影响其他行。

## 状态怎么读

| 状态 | 意思 |
|---|---|
| 已是最新 | 已装的版本 ≥ 远端最新版 |
| 有新版本 | 远端有更新的版本 |
| 没装上 | 依赖里写着，但 `node_modules` 里找不到 |
| 查询失败 | 网络或 registry 出问题 |
| 查不到 | 远端没给出可用版本号 |

## 接口

- `GET /dsh-plugin-watch/status` — 读缓存的体检结果
- `POST /dsh-plugin-watch/refresh` — 立刻体检一次
- `POST /dsh-plugin-watch/update` — 装某一个插件（`{ profile, name, version }`），装前会备份

## 一键更新

「有新版本」的行末尾有个「更新」按钮，点一下就装那一个：

- 装之前照样先把配置文件备份到 `~/.dsh/plugin-watch/backup/`。
- npm 来源的装成面板上显示的那个最新版；GitHub 来源的重新拉一次最新提交。
- **装完不会重启客户端**，下次开客户端才生效。
- 装失败会在页面顶上标红，写明是哪个插件。
